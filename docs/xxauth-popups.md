# Harmony X 3.9.0 无广告分支

基线为 `c579845`。截图中的「纸语」卡片由 XXAuth 推广配置生成，原版将它插入首页、搜索结果和评论列表。开屏推广读取同一套配置和缓存，可在冷启动或从后台返回时显示。这些投放入口、渲染组件、远程开关、素材请求和赞助付款入口已删除。X 返回的推广帖子和探索推广卡片会被过滤，普通帖子的付费合作披露仍可显示。

原版赞助校验向 XXAuth 发送兑换码与 X 账号 ID，后者用作 `machine_code`。版本检查另会发送本地随机生成并持久化的 `device_id`。这两个请求已删除。升级启动会清理旧安装 ID 和设备上保存的旧兑换码。公告、文章和版本信息通过公开 GET 接口读取，版本比较在本地完成，更新提示可关闭。历史服务端数据由原服务端管理。

## 验证和发布

1. 推送分支或提交 PR 后，`Test and build HarmonyX` 运行 Node 回归测试和 API 26 HAP 构建。成功产物可从该运行的 `harmonyx-hap` artifact 下载。
2. 创建 GitHub Release 时，用包含 `.github/workflows/ci-release.yml` 的分支提交创建新标签。直接用旧标签会拿到旧源码。
3. 发布 Release 后，工作流在标签提交上重新测试和构建，将未签名 HAP 和 `SHA256SUMS` 上传到该 Release。安装前需要用符合设备要求的 HarmonyOS 开发者证书和 Profile 签名。

公告与版本功能继续读取 XXAuth 原项目的公开信息，新分支的构建产物以当前仓库 GitHub Release 为准。
